# iris

A small, strict command-line reader for
[Meadow](https://github.com/meadow-lang/meadow). It hands your program one piece
at a time: a short option, a long option or a value. Your program decides what
each piece means, with an ordinary `match`.

This package is a port of Rust's [`lexopt`](https://github.com/blyxxyz/lexopt)
0.3.2. It reads command lines the same way the crate does, including `-abc`,
`-ovalue`, `-o=value`, `--option=value` and `--`, and it gives the same error
messages.

```sh
meadow add meadow-lang/Iris
```

## Use

```meadow
use Iris (parserFromArgs, nextArg, value, parseWith, unexpected, errorMessage, Short, Long, Value)
use Std.String as S

fun number s =
  match S.toInt s with
  | Just n -> Ok (toInt n)
  | None -> Err "not a number"

record Options = { count : Int, name : Maybe String, files : [String] }

fun parse p (opts : Options) =
  match nextArg p with
  | Ok (Just (Short 'n')) ->
    (match value p with
    | Ok v ->
      (match parseWith number v with
      | Ok n -> parse p { opts | count = n }
      | Err e -> Err e)
    | Err e -> Err e)
  | Ok (Just (Long "name")) ->
    (match value p with
    | Ok v -> parse p { opts | name = Just v }
    | Err e -> Err e)
  | Ok (Just (Value file)) -> parse p { opts | files = pushBack opts.files file }
  | Ok (Just other) -> Err (unexpected other)
  | Ok None -> Ok opts
  | Err e -> Err e

def defaults = Options { count = 1, name = None, files = [] }

-- parse (parserFromArgs ["-n3", "--name=x", "a.txt"]) defaults
--   Ok, with count 3 and files ["a.txt"]
-- parse (parserFromArgs ["-n", "many"]) defaults
--   errorMessage: cannot parse argument "many": not a number
-- parse (parserFromArgs ["--verbose"]) defaults
--   errorMessage: invalid option '--verbose'
```

In a real program, start from `parserFromEnv ()`, which reads `argv ()`.

A parser is a mutable cell, so reading from it carries the `Mut` effect.

| function | |
|---|---|
| `parserFromEnv ()`, `parserFromArgs args` | a parser over the arguments, without the program's name |
| `parserFromIter args` | the same, where the first argument is the program's name |
| `nextArg p` | `Ok (Just (Short c))`, `Long name`, `Value v`; `Ok None` at the end; or an error |
| `value p` | the value of the option just read: attached to it, or else the next argument, whatever it looks like |
| `values p` | every value of the option just read: the attached one and the arguments up to the next option |
| `optionalValue p` | the attached value, if there is one |
| `rawArgs p`, `rawPeek p`, `rawNextIf keep p`, `tryRawArgs p` | the remaining arguments as they are |
| `binName p` | the program's name, if the parser was given it |
| `setShortEquals on p` | whether `-o=value` means `value` (on by default) |
| `unexpected arg` | the error for an argument the program did not expect |
| `parseWith parse v` | `parse v`, where a failure `Err reason` becomes `ParsingFailed` |
| `errorMessage e` | the error as the crate words it |
| `debugString s` | `s` quoted as Rust's `{:?}` quotes it |

An `Error` is one of the following. You can also use `Custom` for your own
messages.

- `MissingValue`
- `UnexpectedOption`
- `UnexpectedArgument`
- `UnexpectedValue`
- `ParsingFailed`
- `Custom`

Differences from the crate:

- Meadow strings are always Unicode, so there is nothing like the crate's
  `NonUnicodeValue`.
- The crate's `values()` and `raw_args()` return iterators that read lazily.
  Here `values` and `rawArgs` take every value they would yield, all at once;
  `rawPeek` and `rawNextIf` provide the iterator's `peek` and `next_if`.

## How it's made

`src/Lexopt.mw` is a hand translation of the crate. Its error messages quote
values the way Rust's `{:?}` does. `src/Tables.mw` supports this by listing the
characters Rust writes as `\u{…}`; the list is generated by running the Rust
standard library.

**`src/Cases.mw`** holds 4,000 random command lines. Each one is read by a
random sequence of calls, and the file records what the crate answered to each
call.

Run `scripts/generate.sh` to regenerate; it needs a Rust toolchain.
